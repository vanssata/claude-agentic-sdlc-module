The expensive part is not the answer.

In measured usage, more than 80% of the cost was the main session re-reading its own context, cache read and write, not output. So the session model and the context length are the levers that matter.

where a session’s cost goes
re-reading context · 80%+
output

So it keeps one short always-loaded file per runtime, sends reading and log-crawling to the cheapest model, spends the strong model on plans and reviews, and never fans out agents without a reason.

Four tiers. Named, not guessed.

Prompts name a tier, never a model. Your plan decides what each tier resolves to, and one profile file holds the whole contract. A STRONG or EXPERT agent runs only when a named trigger fires.

Every change gets a tier before a plan.

The tier decides who plans it, who reviews it, and whether a human signs it off. Pick a request and watch what /ai-task would run. Nothing is skipped silently: the profile only changes who does each stage.

    It is harder to damage the project than to change it safely.

    Hooks run before the tool call, in both runtimes, including every file in a Codex apply_patch. A refusal is a signal to take the right path, not a hint to reword.

    cat .env.production

    refused from an agent session: approval is a human’s to give

    Read var/log/prod.log

    runtime-gateboth runtimes
    spawn ai-expert (top model rate-limited)
    rerouted one tier down, and journalled as model_fallback
    context-guardboth runtimes
    prompt at 120% of the compaction point
    held back once. Before compaction a snapshot keeps files, instructions verbatim and task state

    Honest about the limit: the guards are regex tripwires for the ordinary mistake, not a sandbox. Server-side branch protection and human review stay the real backstops, and the README lists every known gap.

    Six tiers. The ceremony scales with the blast radius.

    T0 to T3 run in direct mode: name the files, edit, one verification run at the end, every failure fixed as one batch. T4 and T5 run the full pipeline. A change that reaches **/Payment/** is re-scored from the real diff, and only a human lowers a tier.

    The rest of the machinery.

    Everything runs on deterministic tools first. No model writes or reads the task state.

    One .ai/ tree, two runtimes

    Start a task in Claude Code, resume it in Codex. The state, the journal, the open questions and a thirty-line handoff are plain files both read. state.py handoff --to codex moves it on purpose.

    /ai-init on legacy code

    Surveys an existing codebase and writes a knowledge base, policies and test commands. It never touches application code: problems go to known-risks.md, not into a fix.

    Sensors before reviewers

    review-gate runs your linter, type checker, the diff budget, a re-score and whether the named tests fail without the change. At T2, all green means the sensors are the review.

    /project-update keeps your edits

    Every template version ever shipped is in the plugin, so an update replaces untouched files, three-way merges edited ones and never overwrites a real conflict. --adopt moves Spec Kit, Kiro, Cursor or Copilot setups in, with no line lost.

    /usage-report at zero cost

    Tokens and cost per session, day, project, model and task, from local transcripts, for both runtimes. The numbers above came from it.

    Tested like infrastructure

    25 suites and 2,129 assertions, including an end-to-end run that drives a T4 task from Claude and then from Codex over one state. No suite touches your real home directory.
