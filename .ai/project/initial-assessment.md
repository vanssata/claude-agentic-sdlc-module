# Initial assessment

Snapshot of 2026-11-14 (riskrails 4.2.0, branch `docs/4.2-docs` at `7cf1820`), from a full `/rr-setup` survey: one inventory and six discovery passes. Nothing was run but read-only greps. Recommendations only; none implemented.

## Overview

A Claude Code and Codex plugin: guard hooks, a task state machine with a weight → mode table, skills and an installer. The repository runs its own pipeline (`.ai/`, schema 12). See `overview.md`.

## Architecture

Hooks, the state machine and the skills share on-disk formats but not code. The guard order is decision → git → paths → scope. Hooks fail open on their own errors; the git consent rule and `approve` fail closed. See `architecture.md`.

## Important modules

The guard library (`hooks/guard/`), the state machine (`skills/ai-task/rr_state/`), weight (`weight.py`), project memory (`memory_*.py`), setup and update (`skills/rr-setup/`, `skills/project-update/`), the installer (`bin/riskrails.js`). See `modules.md`.

## Critical business areas

What a user project trusts this plugin to refuse: agent merge, push, publish and approve, and edits to protected paths and out-of-scope files. Also the human gate in full mode and the destructive update confirmations. See `business-rules.md`.

## Legacy hotspots

- Old-shape refusals in project-update (`KEPT_UNREADABLE`, `LAST_MIGRATING_VERSION 3.1.0`).
- Old tier remnants (`tier_set`, `MODE_TIER`) and `_v7` names.

## High-risk integrations

- The Claude Code and Codex hook contracts, under the fail-open doctrine: a broken guard module allows silently.
- The installer writing the user's `~/.claude` and `~/.codex`.
- The npm release workflow.

See `integrations.md`.

## Test and CI maturity

- Strong locally: 65 suites, a byte-compared guard golden, timed cases, characterization suites for state, memory and update, and a parity test between the plugin and npx hook registrations.
- Weaker in CI: a PR runs only 8 of the 65 files (the smoke list, `tests.yml:31-34`) plus e2e. The full suite runs nightly, on dispatch and at release, so a guard, memory or update regression is first seen after merge.
- Branch protection: unverified.

## Security observations

- RISK: fail-open guards. The behaviour is by design, but no signal reaches the user when a guard module fails to import.
- RISK: `AI_UNATTENDED` is interpreted in five places.
- RISK: the consent lock takes over a lock older than 2 s. The questions lock degrades to unlocked on `OSError` (`rr_state/locks.py:46-48,58-84`).
- Secrets: the only ones are `NPM_TOKEN` and OIDC in CI. None are in the code.
- MCP: `.claude/settings.json` is `{}`, so it does not set `"enableAllProjectMcpServers": false` (only the shipped `settings.common.json:9` does). No `.mcp.json`, and no plugin manifest declares a server.
